# 触边运动小模型与越线修正（2026-10-14）

当前动作分两类：轮轴与边线接近平行时，靠边轮用编码器反馈保持位置，内侧轮后退；其他姿态先制动，再原地直接转向主模型选好的目标。两类动作均在完成调整后接回目标，不修改探索网络或黑框停车控制器。

## 两张图的故障判断

已用原始场景配置和固定权重逐步复现，停车时间、触边次数、最大越线与原记录一致。

两次触边目标都在桌内，主要错误出在触边运动执行层的兜底分支。边线估计未满足单轮保持条件时，旧代码继续普通前进圆弧。主模型要求约135度转向，但旧转向器只有超过135度才先制动；等于135度仍有前进速度。车头尚未转回桌内，车身就沿圆弧越出了边线。此时灰色传感器读数已被识别，只是没有制动兜底；不能将原因说成“没有看见边界”或“网络一定选错了方向”。

桌内目标约束只判断目标点，不检查到达目标前的轮子轨迹。触边小网络仅按两个方向输出单轮动作参数；这两次它没有被启用，故障是其外围执行逻辑，并非已有证据证明神经权重预测错误。无需重训主模型。

## 本次改动与回归

1. 保留不超过25度且可确认的单轮保持/内轮后退动作。
2. 其余触边，包括边线估计不确定的情况，先制动两个轮子，用编码器确认残余轮速，再直接原地转向；与目标方向误差不超过5度才恢复前进。
3. 界面持续显示历史最大轮心越线、轮心越线次数和严重越界次数。停车成功只说明最终停车验收通过。
4. 每次新运行记录运动控制器版本，防止把旧轨迹误认为更新后结果。

尚未解决所有单轮越线。传感器触到灰边时，轮心可能已经很靠边；约200毫米/秒的残余轮速不能瞬间消失，原地旋转也有45毫米轮心旋转半径。修正消除了这批样本的严重越界，但某只轮子短时在外的累计时间反而增加。下一步需单独处理提前减速、制动距离和轮子旋转空间，不能用最终停车成功替代过程验收。模拟灰边外仍有支撑，不代表真实桌沿可安全通过。

## 模型与动作如何分工

网络只接收两个方向：主模型选好的目标方向、触边前的原始方向。先转换为相对夹角，再输出内侧轮后退速度和向内转多少。权重只有304字节，运行不依赖PyTorch。模型文件：`models/boundary_motion/policy.bin`。

这两个方向本身不能告诉小车边线在哪里、哪只轮子靠边，因此动作选择器另外使用反射率和编码器估计边线。估计轮轴与边线夹角不超过25度、车头仍朝外、两轮距边有差别，且直边证据充分时，才启用特殊动作。其余情况制动后直接转向。25度是本次仿真阈值，边线估计会有误差。

两条线的夹角按0到90度理解。标作170度的两条线仍接近平行；是否需要特殊动作还取决于车头朝里还是朝外。

网络根据目标方向学会不同的向内转角：主模型相对目标约112.5、135、157.5、180度时，训练筛选的向内倾角分别约22、10、22、35度。后退速度约150毫米/秒。当前选型将“转完后额外直走固定距离”设为0，直接接回原目标，避免走过短子目标。

## 为什么这样做

接近平行且车头朝外时，靠边轮若向前滚就容易越线。以它为支点，让桌内轮后退，能把车头转向桌内。保持轮有电机惯性，零PWM不等于锁住；控制器根据编码器位移和速度补偿，初始惯性位移仍存在。其余姿态直接原地转向，避免一律单轮后退，但先制动以免前进惯性继续带车身越线。

## 初版网络训练与历史结果（本次修正之前）

开发使用24个完整场景：16个训练、8个验证，采集138个实际触边状态。对符合条件的54个状态筛选27组参数，训练时只用训练场景。局部对照从相同位置、朝向、轮速、目标和传感器边线估计开始，不把同一事件的相邻帧拆进训练和验证。单目标局部夹具不重建方向凸包；该目标已经由原主模型和约束选出，完整运行一直保留原约束。

8个完整验证场景，两版均8/8停车。新动作的平均严重越界时间从0.696降到0.475秒；搜索从120.88增加到132.44秒，最坏轮心外探从67.29增加到112.91毫米。按减少平均越界、保持停车成功的目的保留此候选，之后冻结权重。最坏事件还需要继续处理。

再用64个新场景做相同种子的完整搜索和停车配对测试：

| 指标 | 原运动执行器 | 条件触边小模型 |
| --- | --- | --- |
| 正确停车 | 64/64 | 64/64 |
| 错误报告停车完成 | 0 | 0 |
| 平均找到黑框 | 183.49秒 | 176.12秒 |
| 平均完成停车 | 203.07秒 | 196.50秒 |
| 平均整轮支撑代理越线时间 | 7.072秒 | 3.223秒 |
| 平均重心或双轮心越线时间 | 0.340秒 | 0.100秒 |
| 出现重心或双轮心越线的场景 | 19/64 | 8/64 |
| 最坏轮心外探 | 116.48毫米 | 80.43毫米 |

新模型在这批场景上减少了越线，也保持完整停车成功。搜索时间的配对差值95%自助区间为-66.31到50.75秒，不能据此承诺任何场景都更快。全部时间为模拟时间。

保持阶段的最大编码器位移为30.30毫米，主要受触边时已有轮速和仿真假设制动能力影响。它是位置保持控制，不能宣称轮子瞬间静止。仍有8/64个严重越界场景，因此这是已实现并经过仿真验证的改进模型，尚不能保证真桌沿不掉落。边线估计、角落和大角度直接转弯是接下来优先检查的剩余问题。

## 使用与保留

关闭旧仿真窗口后，双击`停车控制台.cmd`运行修正版。两份模型权重保持原哈希；停车与方向约束功能保留，仅修改触边执行和显示。目录精简时的64场景一致性结果属于之前版本，本次运动修正使用新的回归参考，不覆盖历史数据。

验证：先运行`scripts/build.ps1 -WithChecks`，再运行`scripts/verify.py`。训练入口为`experiments/train_boundary_motion.py`，需要NumPy和PyTorch；普通运行只需Processing及其JDK。

逐场景结果和种子位于`experiments/data/fresh_holdout_*`，摘要在同目录`summary.json`。数值推理与Java的一致性最大误差小于0.00001，并验证了方向旋转和左右镜像一致性。整理前源码及校验清单位于项目外归档的`runtime_before_cleanup.zip`。
